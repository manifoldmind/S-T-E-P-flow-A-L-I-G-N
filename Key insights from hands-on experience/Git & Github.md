>Посмотреть статус репозитория на **локальной машине** (что изменилось в **локали** относительно <ins>облака гитхаб</ins>?)
```bash
git status # без предварительных команд просто то что в локали сохранилось последним
```

>Посмотреть статус репозитория на **облачном ресурсе** (что изменилось в **гитхаб** относительно <ins>локального репозитория</ins>)
```bash
git fetch origin # запрос у ГИТХАБ новых последних коммитов: локаль гит -> гитхаб
git status # статус на ГИТХАБ
```

## Ежедневный цикл

1. **Вносите изменения** в файлы (код, документацию, и т.д.).
2. **Просмотрите, что изменилось**:
   ```bash
   git status
   ```
3. **Добавьте нужные файлы в индекс** (подготовьте к коммиту).  
   - Все изменённые и новые (кроме тех, что в `.gitignore`):
     ```bash
     git add .
     ```
   - Или выборочно:
     ```bash
     git add html_parser.py docs/README.md
     ```
4. **Создайте локальный коммит** (контрольную точку):
   ```bash
   git commit -m "Краткое описание того, что сделали"
   ```
   Теперь версия сохранена **локально** в вашем Git.
5. **Отправьте коммиты на GitHub** (синхронизируйте с облаком):
   ```bash
   git push
   ```
   После этого все коммиты появятся на GitHub в вашем приватном репозитории.

## Если вы работаете с нескольких компьютеров

- **Перед началом работы** на другом устройстве сначала заберите последние изменения:
  ```bash
  git pull
  ```
- Затем делайте свои изменения, коммиты и push.

## Полезные сокращения

- После первого `git push -u origin master` (или main) можно использовать просто `git push` и `git pull`.
- Чтобы одновременно добавить все изменённые файлы и сделать коммит одной командой (но аккуратно):
  ```bash
  git commit -am "Сообщение"
  ```
  Это сработает только для уже отслеживаемых файлов (которые были в Git ранее). Новые файлы всё равно нужно добавлять через `git add`.

## Важно

- **Локальные коммиты** — это ваши контрольные точки. Вы можете делать их сколько угодно, даже без интернета.
- **`git push`** — отправляет все накопленные локальные коммиты на GitHub. Если интернета нет, работайте локально, а позже выполните push.

Теперь вы знаете полный цикл: изменяете → коммитите (локально) → пушите (на GitHub). Так ваши версии хранятся и на компьютере, и в облаке.---

## Пустые единичные коммиты
```bash
git commit --allow-empty-message -m " "
```

Для удобства и быстроты также можно вставлять любые свои заглушки при коммите без комментариев, которые будут понятны всем, кто относится к репозиторию, например:
```bash
git commit -m "."
```
Или покреативнее (обычно лень):
```bash
git commit -m "[proc...]"
```

### Локальный гит сохраняет alias-командой
Также есть вариант нашему локальному ПО Git задать новую гит-команду при пушах, которая будет автоматически 1) инициализировать последние изменения, 2) добавлять их с коммитом-заглушкой:
>[!example] Ниже мы называем нашу гит-команду `qc`:
```bash
git config --global alias.qc '!git add . && git commit -m \".\"'
```

Таким образом можем использовать:
```bash
git qc
```
