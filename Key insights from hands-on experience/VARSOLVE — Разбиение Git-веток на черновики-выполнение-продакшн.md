- Ты создаёшь ветку `mindground` и кладёшь туда `__sandbox.ipynb` или любые другие подобные файлы-черновики.
    
- Когда блок кода готов и работает вне зависимости от других, копируешь её в новый файл `src/module.` (папка `src` — часть нашей пространственной структуры), где под `module` — любое название, отражающее завершенный работающий блок. Коммитишь это в ветку `made`.
    
- В ветке `sandbox` черновики остаются нетронутыми, допустимо с комментариями `#PROC`, `#ARCHV`. В `made` лежит чистый модуль с якорем «см. `__sandbox`-файлы».
    
- Можно открыть GitHub и увидеть: на ветке `mindground` папка `src` пустая, зато есть файл-черновик. На ветке `made` — `src/module.` есть, а `__sandbox.` отсутствуют. Это как два разных «архивных снимка» одного проекта на разных стадиях.
    
- `proddone` — ветка продакшна. Туда конечная реализация, которой можно пользоваться целевым пользователям, т.е. ради чего все это...

И да, можно продолжать создавать папки с осмысленными названиями (`docs and handbook`, `experiments`, `stable`). Ветки не диктуют, как называть папки. Они лишь говорят: «на этом срезе проекта вот эти файлы находятся в таком-то состоянии».
